# Avaliação

## 1. Bugs (prioridade alta)

### GET `/core/v1/vector-stores` → 500 (InFailedSQLTransactionError)

- **Causa:** Sessão/connection usada após falha em outra query, sem rollback; ou connection devolvida ao pool ainda em transação abortada (`pool_reset_on_return`).
- **Ação:**
  - No contexto de sessão (`get_session()` em `infra/database`): em um `finally`, chamar `await session.rollback()` antes de `close()` (e tratar/logar falha do rollback).
  - No engine async: usar `pool_reset_on_return="rollback"` para que connections devolvidas ao pool não deixem transação abortada.
- **Não é bug no RagRepository:** cada método já usa uma sessão nova via `get_session()`.

### GET `/core/v1/sla-cases` → 500 (relation "sla_case" does not exist)

- **Causa:** Tabela `sla_case` está na migração inicial `861cb744f4f0`; o erro indica que o banco usado em runtime **não** tem essa tabela (migração não aplicada, outro DB ou schema).
- **Ação:**
  - Rodar `alembic current` no mesmo DB da app e confirmar que está em `861cb744f4f0` (ou revisão posterior que inclui `sla_case`).
  - No mesmo `DATABASE_URL`: checar se a tabela existe (ex.: `information_schema.tables` ou `\dt sla_case`).
  - Se a revisão estiver “current” mas a tabela não existir, criar migração que crie `sla_case` apenas se não existir, ou corrigir o estado do banco e reaplicar.
  - Documentar qual DB cada ambiente usa e garantir que deploy/CI rode `alembic upgrade head` nesse DB.

## 2. Endpoints de execução (flow-runs, node-runs, agent-runs, graph-state)

- **Rotas antigas (deprecated):**
  `ExecutionController` com prefix `/core/v1`:
  - GET `/flow-runs/{id}`, `/flow-runs/{id}/graph-state`, `/node-runs`, `/agent-runs` **retornam 405** de propósito (`MethodNotAllowedPlaceholderException`).
  - POST (create flow-run, tool-run, execute) ainda funcionam, mas estão marcados como deprecated.

- **Rotas canônicas:**
  `ExecutionPlaneController` com prefix **`/core/v1/executions`**:
  - POST/GET flow-runs, tool-runs, node-runs, agent-runs, graph-state, execution-events.
  - O frontend deve usar **só** `/core/v1/executions/flow-runs`, `/core/v1/executions/node-runs`, etc.

- **INTERNAL_ERROR em `/core/v1/executions/*`:**
  Bug a corrigir no fluxo atual (boundary/service/repository): validação de tenant, tratamento de exceção ou uso de sessão. Não criar outro controller; corrigir e adicionar testes de integração para GET flow-run, graph-state, node-runs, agent-runs.

- **Recomendação:**
  Manter as rotas deprecated **documentadas** (ex.: no OpenAPI: “Deprecated. Use /core/v1/executions/...”). Opcional: redirect 307/308 dos GET deprecated para `/core/v1/executions/...`. Remover os GET deprecated só após sunset definido e migração de clientes.

## 3. LIST/GET que faltam (paridade de API)

### Políticas de governance (access, rate-limit, billing, memory, rag)

- **Repos já têm** `list_policies(tenant_id)` para todos.
- **Falta:** no **GovernancePoliciesService** e no **GovernancePoliciesController**:
  - GET list e (opcional) GET by id para: access-policies, rate-limit-policies, billing-policies, memory-policies, rag-policies.
- **Padrão:** igual ao de runtime-policies (mesmo recurso: GET list + POST create).
- **DB:** Garantir índice em `tenant_id` (e, se fizer ORDER BY, composto ex.: `(tenant_id, created_at)` ou `(tenant_id, name)`). LIST com `limit`/`offset` e limite máximo (ex.: 100).

### Node–agent e tool–agent (por agent_version)

- **Listar nodes por agent_version:**
  Não existe. **Onde:** `AgentsRepository`: método tipo `list_node_ids_by_agent_version_id(agent_version_id)` (ou listar bindings); expor no controller, ex.: GET `/core/v1/agent-versions/{agent_version_id}/nodes` ou sob agents.

- **Listar tools (ou bindings) por agent_version:**
  Não existe. **Onde:** `ToolsRepository`: método tipo `list_tool_bindings_by_agent_version_id(agent_version_id)`; expor ex.: GET `/core/v1/agent-versions/{agent_version_id}/tools` (ou equivalente sob agents/tools).

## 5. Modelos não gerenciáveis via API / endpoints deprecated

- **Modelos sem API de gestão (hoje):**
  flow_graph (só create), flow_graph_draft (só POST), flow_graph_snapshot, router (sem get por id), routing_rule (sem list), run_failure, interaction (sem get/list), response_artifact (sem list), end_user, user_preferences, user_memory_profile (sem API dedicada).
  Priorizar conforme contrato do frontend; evitar endpoints “por speculação”.

- **Deprecated e seguros de remover (no longo prazo):**
  Apenas os **GET/list** do `ExecutionController` em `/core/v1` (flow-runs, node-runs, agent-runs, graph-state), que já retornam 405. Remover só após sunset e migração para `/core/v1/executions`.
  **Não** remover os POST deprecated em `/core/v1` antes de os clientes usarem POST em `/core/v1/executions`.

- **Recomendação (governance + DB):**

- **Implementação sugerida (DB):**

- **Escopo:**
  Contagens sempre por `tenant_id` do auth; sem agregação cross-tenant.
